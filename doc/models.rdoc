= Models

A model is a class of record: declared attributes, declared relationships,
one instance per id, and a transport. Subclass <tt>Swill::Model::Base</tt>.

  class Menu < Swill::Model::Base
    endpoint "/api/menus"
    resource_type "menus"

    attribute :name, type: String, default: ""
    has_many :recipes, type: MenuRecipe, key: "menu_recipes",
             url: "/api/menus/:id/recipes"
  end

== Class configuration

endpoint :: The collection URL. Required before any read or write;
            <tt>endpoint_url</tt> raises without it.
resource_type :: The JSON:API type this class answers to. Required for the
                 default codec: a payload's resource is matched to the class
                 declaring that type.
codec :: <tt>Swill::Model::PlainJSON</tt> for a plain JSON endpoint.
         <tt>Swill::Model::JSONAPI</tt> is used when none is declared.

Each setting reads through to the superclass until the subclass writes it.

== Identity

<tt>id</tt> is declared for every model: <tt>T.nilable(String)</tt>, nil
until the server assigns one. A record with no id is unsaved.

Each class keeps one pool, one instance per id. Everything parsed from a
payload is pooled, and a second instance arriving with a pooled id has its
attributes applied to the instance already there and is discarded — so
observers and bindings never split across two copies of a record.

Menu.get(id) :: The pooled instance, or nil. No request.
Menu.pooled?(id) :: Whether the pool holds that id.
Menu.put(record) :: Pool the record; answers the pooled instance, which may
                    not be the argument. Raises without an id.
Menu.remove(id), Menu.clear, Menu.values :: The rest of the pool.

== Attributes

  attribute :name, type: String, default: ""
  attribute :serves, type: T.nilable(Integer), default: nil, key: "serving_count"

type :: Required.
default :: Required. Immutable literals and empty collections only.
key :: The wire key. The attribute name unless declared.

An attribute is an observable property: reading it records a dependency and
writing it notifies observers.

A class may declare <tt>validate_<name>(value, previous)</tt>. It runs on
every write, including construction from a payload, and answers the value to
store — so it coerces as well as checks. It may raise to reject the write. A
validator taking any other arity is an error.

record.collect_attributes :: Attribute values by wire key.
record.apply_attributes(hash) :: Write values from a wire hash. Clean.
Menu.from_attributes(hash) :: A new instance with those values.

=== Dirty tracking

<tt>dirty_attributes</tt> and <tt>dirty?</tt> are observable, so a save
button binds to them.

Only writes through setters mark an attribute dirty. Anything applied by the
codec, the server, or a draft is clean. An attribute written back to the
value it held when tracking began leaves the dirty set.

record.dirty :: The dirty attribute names.
record.collect_dirty_attributes :: Their values by wire key — what a PATCH
                                   carries.
record.mark_clean! :: Forget the baseline and the dirty set.

=== Drafts

<tt>draft</tt> answers a new unpooled instance carrying a copy of the
attributes; edit it, then <tt>apply_draft(copy)</tt> on the original to take
the values back. Application is clean.

== Relationships

  has_many :recipes, type: Recipe, key: "menu_recipes", url: "/api/menus/:id/recipes"
  has_one  :author,  type: Person

type :: Required. The model class, or its name as a string when the class is
        declared later.
key :: The wire key, used for relationship linkage in a document and for the
       default URL. The relationship name unless declared.
url :: The collection URL, where <tt>:id</tt> stands for the owner's id.
       Without it, the owner's resource URL followed by the key.
will_access :: <tt>false</tt> to suppress loading on read.

A to-many value is an array, empty until loaded; a to-one is nil.

Each relationship also declares <tt><name>_loading</tt>,
<tt><name>_loaded</tt>, and <tt><name>_error</tt>. All are observable, so a
spinner, an empty state, and a failure message are bindings.

=== When they load

Reading the value on a persisted record that has not loaded it starts the
request and fills the value in when it lands. Binding to the value is all a
view needs. The read does not load when the record has no id, when the
relationship is already loaded, while a request is in flight, or when a
previous attempt failed — a remembered failure stops the retry, and
<tt>reload_<name></tt> is how an application asks again.

await record.load_recipes :: The records, from the server the first time.
                             Answers what is loaded otherwise.
await record.reload_recipes :: Asks the server regardless. Concurrent callers
                               share one request; the caller receives the
                               rejection after the error state is written.
record.relationships, record.relationship(name) :: The installed descriptors:
                                                   name, key, many?,
                                                   model_class, url_for.
record.relationship_loaded?(name) :: Whether it has a value.
record.assign_relationship(name, value) :: Set it. Assignment counts as a
                                           load: loaded, no error.

A JSON:API document hydrates relationships from its own resources: every
resource in <tt>data</tt> and <tt>included</tt> is pooled first, then linkage
is resolved from the pool, so order does not matter. A linkage naming a
record the document did not carry leaves the relationship unloaded rather
than partly filled.

== Reading

  menu  = await Menu.find(id)
  menus = await Menu.where({"status" => "published"})

await Menu.find(id) :: The pooled instance, or a fetch.
await Menu.fetch(id) :: The server's record, pooled, whatever the pool held.
                        Raises if the endpoint answers nothing.
await Menu.find_all :: Every record at the endpoint.
await Menu.where(params) :: The endpoint with query parameters.
await Menu.fetch_all(url, params) :: A collection at any URL, parsed as this
                                     class.
Menu.parse_one(payload), Menu.parse_many(payload) :: Parse and pool a payload
                                                     already in hand.

=== Datasets

<tt>Menu.dataset(url, params)</tt> answers a <tt>Dataset</tt>: one collection
request as observable state — <tt>records</tt>, <tt>loading</tt>,
<tt>error</tt>. It holds no records until <tt>await dataset.reload</tt>, which
may be called again for the same URL. A failure is reported on
<tt>error</tt>, not raised.

== Writing

await record.save :: <tt>validate</tt> first, and its message raises rather
                     than saving. A record with no id is POSTed with all its
                     attributes; a dirty record is PATCHed with the dirty ones
                     only. A clean persisted record is a no-op. The response
                     is applied, and the record is clean and pooled.
await record.delete :: DELETE, then leave the pool. A record with no id is a
                       no-op.
await record.reload :: The server's current attributes, applied here; the
                       record is clean.
record.validate :: Answers an error message that refuses the save, or nil.
                   Override it for whole-record checks; per-attribute checks
                   belong in <tt>validate_<name></tt>. nil by default.
record.serialize(dirty_only) :: The payload the codec would send.

The id is identity, never a saved attribute: the codec strips it from the
attribute payload and carries it separately.

== Transport

Every request goes through <tt>Swill::Wire.default</tt>, which calls the page's
<tt>fetch</tt>. It carries <tt>base_url</tt>, sends JSON and form bodies, answers
nil for a 204, and raises on a failed status. Replace it to test without a
server.

== Remote data

A model backed by the data connection declares its shape rather than an
endpoint. These declarations are what the schema generator emits.

  class Recipe < Swill::Model::Base
    remote_model "Recipe"
    remote_attribute :title, type: String
    remote_has_one   :author, model: "Person"
    remote_has_many  :steps,  model: "Step"
  end

remote_model(name) :: The server model this class stands for.
remote_attribute(name, type:) :: One field. No default and no wire key: a
                                 remote field is nil until it is present.
remote_has_one(name, model:) :: A nilable record. <tt>model</tt> is the
                                server model's name.
remote_has_many(name, model:) :: A <tt>Collection</tt>, present from
                                 construction.

Remote fields differ from attributes in what they promise. They carry no
default and are not dirty-tracked — they are the server's values, not an
edit buffer — and their presence lives outside the value, so a field that has
not loaded and a field the server says is nil both read as nil. Ask the
presence, not the value:

record.field_loaded?(:title) :: Whether the server has answered.
record.field_loading?(:title) :: Whether a request is in flight.
record.field_error(:title) :: The last failure, or nil.
await record.load_field(:title) :: The value, requesting it if it is not
                                   present.
await record.reload_field(:title) :: Requests it regardless.

Reading a remote field on a record with an id demands it. Demands raised in
the same turn are coalesced into one request per record, and a failure is
reported on the field rather than raised — an explicit
<tt>load_field</tt>/<tt>reload_field</tt> is what gives a caller the
rejection.

Generated classes also carry the server's declared operations:
<tt>query</tt> and <tt>resolver</tt> become class methods, <tt>command</tt>
becomes an instance method sent with the record's id. All are awaited. A
query answering a list answers a <tt>ResultSet</tt>.

== Collections

<tt>Collection</tt> is stable membership for a query result or a to-many
remote relationship. It is observable throughout: <tt>records</tt>,
<tt>loading</tt>, <tt>loaded</tt>, <tt>error</tt>, with <tt>first</tt>,
<tt>last</tt>, <tt>at(index)</tt>, <tt>size</tt>, <tt>empty?</tt>,
<tt>loaded?</tt>, <tt>loading?</tt>. <tt>replace(records)</tt> sets the
membership and marks it loaded with no error.

<tt>ResultSet</tt> is a <tt>Collection</tt>, and is what a remote query
answers.
