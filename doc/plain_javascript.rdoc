= Plain JavaScript, without a build step

Load <tt>swill.js</tt>, register ordinary JavaScript classes, then start the
application explicitly. Put these scripts at the end of <tt>body</tt> so the default
root, <tt>document.body</tt>, is ready.

  <main controller="Hello">
    <h1 bind="greeting"></h1>
    <input bind="name">
    <button data-action="clearName">Clear</button>
    <p outlet="status"></p>
  </main>
  <script src="swill.js"></script>
  <script>
    class Hello extends Swill.Controller {
      static properties = {
        name: {default: "Ada"},
        items: {default: () => []}
      };

      static outlets = {
        status: {},
        optionalPanel: {optional: true}
      };

      static actions = ["clearName"];

      get greeting() {
        return `Hello ${this.name}`;
      }

      awakeFromDOM() {
        this.status.element().textContent = "Ready";
      }

      clearName() {
        this.name = "";
      }
    }

    Swill.register(Hello);
    const application = Swill.start();
  </script>

Every native getter on a registered class is an observable computed property.
Dependencies are collected while the getter runs. Scalar properties may use a
literal default; arrays and objects use a zero-argument factory so instances do
not share mutable state. Actions are explicit and accept zero, one, or two
arguments; the framework supplies the sender and DOM event when requested.
Outlets are required unless their descriptor has <tt>optional: true</tt>.

Controller subclasses may override <tt>bindingRoot</tt>, <tt>decodeOutletData</tt>,
<tt>viewDidLoad</tt>, <tt>awakeFromDOM</tt>, <tt>controllerDidRestore</tt>, <tt>controllerDidLoad</tt>,
<tt>viewWillAppear</tt>, <tt>viewDidAppear</tt>, <tt>viewWillDisappear</tt>, and
<tt>viewDidDisappear</tt>. Outlets are connected after <tt>viewDidLoad</tt> and before
<tt>awakeFromDOM</tt>. Application subclasses may override <tt>applicationDidLaunch</tt>
and <tt>applicationWillTerminate</tt>. <tt>Swill.List</tt> subclasses may override
<tt>makeRowElement</tt>, <tt>configureRow</tt>, <tt>rowsAreViews</tt>, <tt>isRowElement</tt>,
<tt>selectedObjectDidChange</tt>, and <tt>activateSelection</tt>.

Known gap: property change hooks are not yet available to JavaScript
classes. The runtime dispatches <tt>name_did_change</tt> from a class's installed
method table, and <tt>Swill.register</tt> fills that table only from `static
actions<tt>, so a </tt>nameDidChange` method on a registered class is never called.
Observe the property instead: <tt>this.observe("name", (value, previous) => ...)</tt>
in <tt>viewDidLoad</tt>, or <tt>this.observeWithObject(other, "name", ...)</tt> for another
object's; both are released at <tt>unload</tt>. Closing the gap means registering hook methods in the
table; their names already match, since compiled members are camelCase.

<tt>Swill.register("Admin::Editor", Editor)</tt> supplies a markup name explicitly.
Register a JavaScript parent before its subclasses. For another root or a
custom registered application class, use
<tt>Swill.start({root: element, application: MyApplication})</tt>. One application
runs per page, as one <tt>NSApp</tt> runs per process: <tt>start</tt> returns it,
<tt>Swill.Application.shared()</tt> is it from anywhere, <tt>Swill.Application.isRunning()</tt>
says whether one is up, and a second <tt>start</tt> while it runs is an error.

JavaScript methods use JavaScript semantics. Markup bindings retain Swill's one
shared value rule: only <tt>false</tt>, <tt>null</tt>, and <tt>undefined</tt> are false for checkboxes
and boolean <tt>bind-*</tt> properties.

See <tt>examples/rb/javascript.html</tt> for a complete page.

== Browser checks

  # macOS default Chrome path
  BUNDLE_PATH=vendor/bundle bundle exec rake browser

  # Explicit browser
  CHROME_BIN=/path/to/chrome BUNDLE_PATH=vendor/bundle bundle exec rake browser

The check uses Chrome's DevTools protocol with a temporary profile. It exercises
both compiled Ruby and plain JavaScript applications, including class lookup,
manual startup, input events, computed rendering, nested controller ownership,
actions through the responder chain, and listener release.

For manual inspection:

  BUNDLE_PATH=vendor/bundle bundle exec rake build
  python3 -m http.server 3000 --bind 127.0.0.1

Open <tt>http://127.0.0.1:3000/examples/rb/javascript.html</tt> for the no-build
JavaScript example. <tt>examples/rb/index.html</tt> demonstrates compiled Ruby: it
declares its application and loads the two scripts.

  <body application="Demo::Application">
    <main controller="Demo::Controller">...</main>
    <script src="../../rb/dist/swill.js"></script>
    <script src="../../rb/dist/app.js"></script>
  </body>

Load <tt>swill.js</tt> before <tt>app.js</tt>. The framework launches the named application
on <tt>DOMContentLoaded</tt> and terminates it on a real <tt>pagehide</tt>.

== Dependency updates

Ruby2JS tracks a lockfile-pinned upstream commit because the latest published gem
does not include the Pragma filter.

  BUNDLE_PATH=vendor/bundle bundle update
  BUNDLE_PATH=vendor/bundle bundle exec rake
  BUNDLE_PATH=vendor/bundle bundle exec rake browser

Commit <tt>Gemfile.lock</tt> after verification.
