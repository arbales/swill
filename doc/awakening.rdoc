= Awakening, Hydration, and Templates

Swill treats server HTML as an object graph waiting to be awakened. The DOM gives placement, nesting, and initial content. Attributes say which elements become framework objects.

== Managed Elements

A live element is managed when it has <tt>klass</tt>, <tt>controller</tt>, or <tt>outlet</tt>.

  <section controller="MovieList" outlet="movieList">
    <header outlet="headerView"></header>
  </section>

<tt>controller="MovieList"</tt> creates a <tt>MovieList</tt> controller and attaches it to the element's <tt>View</tt>.

<tt>klass="List"</tt> means "awaken this HTMLElement as an object of class <tt>List</tt>." Today the class must be a <tt>View</tt> subclass, because <tt>View</tt> is the framework's DOM boundary. This is intentionally broader language than "view class" so the markup model can evolve without changing the attribute.

<tt>outlet="headerView"</tt> creates a plain <tt>View</tt> when no <tt>klass</tt> or <tt>controller</tt> is present. That view is then connected to the nearest owning controller outlet with the same name.

<tt>klass</tt> and <tt>controller</tt> can appear together. That means "wrap this element in <tt>klass</tt>, create this controller, and set the controller's <tt>view</tt> to that object."

== Inert Elements

Elements with only <tt>bind</tt>, <tt>bind-*</tt>, or <tt>data-action</tt> stay raw DOM. Bindings and actions attach behavior to them, but they do not become <tt>View</tt> or <tt>Controller</tt> objects.

  <button data-action="save" bind-disabled="@saving">Save</button>

This keeps the object graph sparse: only elements that need identity become objects.

== Ownership

DOM nesting is a signal, but ownership follows the sparse <tt>View</tt> tree.

Each <tt>View</tt> has a <tt>controller</tt> only when it is that controller's root view. Outlet views leave it nil; their region owner is found with <tt>view.owner</tt>.

An action walks the responder chain from the responder that received it. The first responder implementing the action handles it; otherwise the search continues through <tt>next_responder</tt> — parent controllers, then the application. An action no responder implements raises.

== JSON Outlets

JSON script outlets are inert as DOM objects but are available to outlet connection:

  <div controller="MovieList">
    <script type="application/json" outlet="represented_object">
      []
    </script>
  </div>

The owning controller may override <tt>decode_outlet_data(name, value)</tt> to turn that JSON into models before assignment. This is the forward-compatible path for server-provided represented objects.

== Pre-rendered Content

Pre-rendered rows can live inside an outlet region:

  <div controller="MovieList">
    <script type="application/json" outlet="represented_object">[]</script>
    <section outlet="rows">
      <div class="row">Pre-rendered by the server</div>
    </section>
  </div>

The <tt>rows</tt> section becomes the owned view. The row DOM remains plain DOM unless a row itself carries <tt>klass</tt>, <tt>controller</tt>, or <tt>outlet</tt>.

== Templates

Templates are inert. They are scanned as named content, not awakened in place.

Window content templates use either:

  <template for="window" name="members">...</template>

or the shorter top-level form:

  <body>
    <template name="members">...</template>
  </body>

Window slots use <tt>[window]</tt>:

  <section window="main" name="lists"></section>

If the window slot is empty, Swill loads content from a matching template or captured pre-rendered content. If the URL fragment asks for different content than the pre-rendered default, Swill skips adopting the stale content when it can load the requested content instead.

Use templates for reusable or switchable window content. Use live DOM for content that should be visible and awakened at launch.
